## Reproduced defect and shared policy

Sanitized fixture screenshots, captured immediately after the row click in both versions:

| Viewport         | Before                                                        | After                                                       |

| Desktop 1440×900 | [Before](evidence/content-navigation/desktop-1440-before.png) | [After](evidence/content-navigation/desktop-1440-after.png) |
| Mobile 390×844   | [Before](evidence/content-navigation/mobile-390-before.png)   | [After](evidence/content-navigation/mobile-390-after.png)   |

The Reshare row button only changed `formTargets`. The form mounted before the table, outside the current document viewport. The original production-bundle regression failed at the immediate `toBeInViewport()` assertion on both desktop and mobile (intersection ratio 0); no input action ran before that assertion. The 20-row fixture identifies products and sources independently, scrolls more than 500 CSS pixels, and records URL, active element, heading rectangle, scroll owner, screenshots and mutation requests. Row actions use their own product/source even when another checkbox is selected.

`revealContent` focuses an explicit destination with `preventScroll`, then moves vertical scroll owners only. Horizontal tables and tab bars retain their independent offsets. Movement is immediate, including reduced-motion mode. The mobile menu offset is 72 px at widths up to 820 px, 16 px otherwise. Opening a form focuses its heading, not the numeric input.

`RouteContentNavigation` lives inside the authenticated shell, keyed by account and role. Real page/panel/detail mounts announce readiness; skeletons do not. PUSH/REPLACE to another page target the heading; tab and supported detail query changes select their destination; filter/page changes remain in place. POP uses an in-memory per-history-entry position (bounded to 100 entries). A ResizeObserver can finish restoration after content grows; it is disconnected on success, user interaction, navigation or shell teardown. Pending route intent is cancelled by user interaction. Hash targets use their actual ID. Nothing is persisted in URL or storage beyond existing navigation parameters.

## Data and permission boundary

Verified call chain: `supplierApi.ts` → contracts → API repository/policy and postgres supplier repository → database supplier reconciliation. ADMIN and HTKD retain management access; store/wholesale views remain scoped orders. Only preview's optional AbortSignal changes in the API client. No server contract, domain formula, worker, SQL, migration, role or legacy-data change. Opening and closing UI does not call confirm or mutate stock/RE status.

## Coverage boundaries

- Shared route audit checks all policies, actual allowed menu clicks and reachable tabs. Dedicated workflows exercise the business controls named above. The JSON's list of buttons is an inventory, not proof that every destructive button was clicked.
- Source-only inspection of some Admin editor actions is identified above; this change does not invent production account mutations to enlarge coverage.
- Production fixture tests cover 360/390/412, 768/1024, 1366/1440/1920/2560 and breakpoint 819/820/821. Actual browser zoom uses the existing extension-backed 100/125/150% helper, not CSS zoom or viewport substitution. Reduced motion and keyboard behavior have separate assertions.
- Local/CI test data is isolated PostgreSQL. Production verification is read-only and reported separately in the release evidence. Missing production roles or data must remain explicitly unverified.

### Data-backed hash anchors

The page heading can mount before the catalog table. A missing anchor no longer consumes the intent; catalog announces its table heading after data mounts. Desktop/mobile hash tests reproduced missing focus/viewport, then all 12 focused navigation tests passed after the readiness fix.
